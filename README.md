# Архитектурная модель системы электроусилителя руля (EPS)

**Автор:** Денис Шендаков, студент РТУ МИРЭА (Системный анализ и управление)
**Методология:** ARCADIA / MBSE
**Инструменты:** Eclipse Capella, Python (для имитационного моделирования)

## Описание проекта
Проект представляет собой полный цикл системного анализа и проектирования архитектуры электроусилителя руля (EPS) для легкового автомобиля. Разработка выполнена на четырёх уровнях абстракции по методологии ARCADIA, от анализа операционных потребностей до физической реализации и программной верификации требований.

## Цели и ключевые метрики (TO BE)
Система спроектирована для решения проблемы высокого физического усилия при маневрировании и отсутствия объективной диагностики. 
Целевые утвержденные показатели:
* Снижение усилия на рулевом колесе до ≤ 5 Н·м.
* Время отклика системы (руль → колёса) ≤ 10 мс.
* Наработка на отказ (MTBF) ≥ 150 000 ч.
* Обеспечение функции fail-safe (механическая связь при отказе электроники).

## Этапы проектирования

### 1. Операционный анализ и потребности системы (Operational & System Need Analysis)
* Выявлены заинтересованные стороны (Водитель, Техник обслуживания, ОЕМ) и их потребности.
* Проведён Trade-off анализ 4 концепций (Механика, ГУР, ЭГУР, EPS) методом взвешенных сумм. Обоснован выбор EPS.
* Сформирован системный контекст и определены 10 ключевых системных требований (SyR).

### 2. Логическая архитектура (Logical Architecture)
Система декомпозирована на 5 логических компонентов:
* Модуль восприятия воздействия
* Модуль обработки и управления
* Модуль усиления воздействия
* Модуль передачи воздействия
* Модуль диагностики

*(Здесь стоит добавить ссылку на картинку диаграммы: `![Logical Architecture](./diagrams/LAB_logical_architecture.png)`)*

### 3. Физическая архитектура (Physical Architecture)
Определены 6 физических узлов (датчики момента и угла, ЭБУ, двигатель PMSM, рулевая рейка, блок диагностики с CAN-интерфейсом). Разработана сквозная матрица трассировки требований (от SR до PFR).

## Верификация требований
Разработана имитационная модель на языке Python (`eps_verification.py`) для проверки 6 ключевых требований (SyR-1, SyR-2, SyR-4, SyR-5, SyR-6, SyR-9). 
Моделирование включало 3 сценария (парковка, высокая скорость, отказ усилителя). По результатам пакетного прогона (25 итераций) архитектура подтвердила 100% успешность (Pass rate) по всем проверяемым метрикам.
